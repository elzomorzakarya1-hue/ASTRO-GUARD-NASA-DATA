ASTRO-GUARD — ACCOUNT EDITION / FINAL POLISH
=============================================

ما الذي تتضمنه النسخة؟
----------------------
- صفحة Introduction فضائية مع صورة Earth مضغوطة بصيغة WebP.
- إنشاء حساب، تسجيل الدخول والخروج.
- كلمات المرور تُخزّن بتجزئة PBKDF2-HMAC-SHA256 مع Salt عشوائي، وليس كنص واضح.
- قاعدة SQLite محلية تحفظ مساحة عمل منفصلة لكل حساب.
- حفظ واستعادة بيانات ASTRO-GUARD وMission Systems والـ XP.
- مؤشر اتصال يختبر السيرفر وقاعدة البيانات على صفحة البداية.
- نافذة تسجيل قابلة للتمرير على الشاشات الصغيرة، وأزرار SHOW/HIDE لكلمة المرور.
- نفس صفحات النظام والـ Daily Check-in ونظام +25 XP.
- اختبارات API محلية، ومشغلات Windows وmacOS/Linux.
- لا يحتاج تثبيت أي مكتبات Python أو JavaScript إضافية.

التحديث من نسخة سابقة مع الحفاظ على الحساب
-------------------------------------------
- قبل استبدال النسخة، أوقف السيرفر القديم بـ Ctrl+C.
- انسخ مجلد instance من مجلد المشروع القديم إلى مجلد المشروع الجديد بعد فك الضغط.
- إذا سأل Windows عن الدمج، وافق على دمج المجلدات؛ لا تحذف ملف astro_guard.sqlite3.
- لا تستبدل قاعدة البيانات بقاعدة فارغة. خذ نسخة احتياطية من instance أولًا.

تشغيل Windows / VS Code
-----------------------
الطريقة الأولى:
1) فك ضغط ASTRO_GUARD_FINAL_POLISHED.zip.
2) افتح مجلد ASTRO-GUARD بالكامل في VS Code من File > Open Folder.
3) افتح Terminal > New Terminal.
4) شغّل:  py app.py
   أو:     python app.py
5) افتح:   http://127.0.0.1:8000
6) اترك نافذة Terminal مفتوحة أثناء الاستخدام.

الطريقة الثانية:
- اضغط مرتين على run_windows.bat.

macOS / Linux
-------------
افتح Terminal داخل مجلد المشروع وشغّل:
    ./run_unix.sh
ثم افتح http://127.0.0.1:8000.

إنشاء حساب واستخدامه
--------------------
- من صفحة Introduction اضغط CREATE ACCOUNT.
- أدخل اسم عرض، بريدًا بصيغة صحيحة، وكلمة مرور لا تقل عن 8 أحرف.
- البريد هنا معرّف دخول محلي فقط؛ لا يتم إرسال رسالة أو تأكيد البريد.
- بعد إنشاء الحساب، ستفتح لوحة ASTRO-GUARD.
- في المرات التالية استخدم SIGN IN.
- LOG OUT يحفظ مساحة العمل أولًا ثم ينهي الجلسة.
- عند وجود بيانات محلية قديمة، قد يظهر خيار استيرادها للحساب الجديد.

البيانات والنسخ الاحتياطي
-------------------------
- تنشأ قاعدة الحسابات تلقائيًا داخل instance/astro_guard.sqlite3.
- كل حساب مرتبط بمساحة عمل منفصلة.
- لا تحذف مجلد instance؛ فهو يحتوي على الحسابات والجلسات وبيانات العمل.
- للنسخ الاحتياطي: أوقف السيرفر بـ Ctrl+C، ثم انسخ مجلد instance إلى مكان آمن.
- لا ترفع مجلد instance إلى GitHub ولا تشاركه؛ يحتوي على بيانات الحسابات.
- ملف .gitignore يستثني instance وملفات Python المؤقتة من Git.

اختبار السيرفر
--------------
من Terminal داخل مجلد المشروع شغّل:
    python test_local_server.py
الاختبار ينشئ قاعدة بيانات مؤقتة ومعزولة، ولا يغيّر قاعدة بياناتك الأساسية.

إذا واجهت مشكلة تشغيل
---------------------
- يجب أن ترى في Terminal رسالة ASTRO-GUARD local account server is running.
- افتح العنوان http://127.0.0.1:8000، ولا تفتح index.html مباشرة.
- لا تستخدم Live Server / Go Live؛ لأنه لا يشغّل API الحسابات.
- إذا كان المنفذ 8000 مستخدمًا، أغلق التطبيق الذي يستخدمه أو شغّل في CMD:
      set PORT=8001
      py app.py
  ثم افتح http://127.0.0.1:8001.
- إذا ظهرت LOCAL SERVER NOT CONNECTED أسفل صفحة المقدمة، راجع Terminal.

حدود الاستخدام والسلامة
-----------------------
- هذه نسخة محلية للعرض الطلابي، وليست خدمة سحابية عامة.
- الحسابات تعمل على الجهاز الذي يشغّل السيرفر فقط، ولا تتم مزامنتها تلقائيًا بين الأجهزة.
- لا يوجد تأكيد بريد إلكتروني أو استعادة كلمة مرور أو إدارة حسابات سحابية.
- استخدم كلمة مرور تجريبية وفريدة؛ لا تستخدم كلمة مرورك الحقيقية.
- لا تدخل بيانات صحية أو طبية حقيقية. استخدم بيانات تجريبية فقط.
- ASTRO-GUARD نموذج طلابي وليس جهازًا طبيًا أو نظامًا تشغيليًا معتمدًا. لا يشخّص ولا يصف علاجًا ولا يتصل بأجهزة طبية أو مركبة فضائية ولا يرسل تنبيه طوارئ حقيقيًا.
- في أي طارئ حقيقي، اتبع الإجراء المعتمد وقناة الاتصال الرسمية فورًا، ولا تنتظر التطبيق.

تحديث مكتبة بيانات NASA — 14 نوفمبر 2026
---------------------------------------
- صفحة NASA Data Observatory تشرح الفرق بين كتالوج data.nasa.gov العام ومستودع OSDR المتخصص في علوم الحياة المرتبطة بالفضاء.
- أضيفت دراسات Inspiration4 البشرية: OSD-569 (عينات دم كامل)، OSD-570 (خلايا مناعية PBMC)، OSD-575 (مصل الدم والتحاليل الأيضية والسيتوكينات)، OSD-656 (لوحة التهاب البول)، وOSD-574 (خزعة الجلد والميكروبيوم).
- زر LOAD IN INSPECTOR يضع رقم الدراسة في مستعرض OSDR ويطلب بيانات الدراسة الوصفية فقط؛ لا يستورد قياسات إلى سجل الطاقم.
- يجب إبقاء بيانات العينات البحثية القديمة داخل Research Data Lab منفصلة عن Daily Check-in وPhysiology. بعض البيانات المعالجة متاحة للعامة، بينما تتطلب بعض ملفات التسلسل الخام وصولًا مضبوطًا.
